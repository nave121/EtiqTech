## Risks
- **Riskiest: the regex (step 2).** A pattern that matches too much passes weak monitoring again; one that matches too little floods approved protocols with warnings. Blast radius: every severity ≥4 report, and merging to `main` deploys. Mitigation: the firing table on every real export must equal the chosen row in spec.md, and a 25-phrase self-check covers the edge words (`יומיים`, `כל שבועיים`, every 10 days, every 12h).
- **Default gate (step 2).** An error where a warning was decided would fail approved protocols. Mitigation: `batch_process.py examples/known-good --fail-on-error` and the per-export status diff in both profiles.
- **Test and manifest edits (steps 3, 4).** F1 and F2 are decided (D4); the diff must show no other test or manifest change.

- **A separate warning tier for "nothing every 48 h"** (V2 as advisory). More code, and Razy declined V2.
- **Moving the regex to `helpers.py`.** One rule uses it.

## Deviations
- **D1. The batch proof needs `PYTHONPATH=.`.** `python scripts/batch_process.py ...` as written above exits 1 with `ModuleNotFoundError: No module named 'src'`; run as `PYTHONPATH=. python scripts/batch_process.py examples/known-good --fail-on-error` it prints `Passed: 35`, `Failed: 0` and exits 0.
- **D2. Fixes after an independent review (Razy: "fix the five do-now items").** The review passed the diff with no wrong verdict on any real export; each finding below was re-run before fixing.
  1. The regex missed common phrasings ("twice weekly", "2x/week", "q12h", "on alternate days", "every 24 to 48 h", `פעמיים ביממה`, `כל יממה`, `מידי יום`, `כל שלושה ימים`, `כל 2-3 ימים`, `כל שעתיים`) and leaked past its limits ("every 200 hours", "every 6-7 days"). Rewritten with hours capped below 168, day ranges capped at 6, ranges with `-`, `to` or `עד`, and `יומי` no longer matching inside a word (`קיומי`) or on a weekday (`כל יום שני`). Self-check: 51 phrases that must pass and 28 that must not, all right.
  2. `ongoing_per_week` accepts `2.0` (the schema allows it); a stated cell, even once a week, is a plan, so "has no monitoring plan" now needs no text and no cell. This refines spec R1 and decision D3 for the cell case only.
  3. `src/schema.py` and the generated `docs/schema.md` still stated the old "daily in the first 72h, weekly afterward" rule. Reworded to the 1.3.0 rule. These x_meta rules also go into the Layer 2 and Layer 3 prompts (`src/llm_agent.py`, `src/llm_layer3.py`), so the LLM now gets the same rule as Layer 1: a departure from the intent's "no LLM change" (intent.md:33). Advisory only; Layer 1 is not touched by it.
  4. Tests added for the export cells, the weekly-or-rarer negatives, the new phrasings and the warning/error counters.
  5. Known limit kept, as a `shortcut:` comment and here: the regex matches frequency words, not what is checked, so "daily dose", "reduced daily food intake", `פעילות יומיומית` and "weekly; daily if signs appear" pass.
